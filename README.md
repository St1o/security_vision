# Security Vision

Система компьютерного зрения для контроля применения СИЗ на строительной площадке (учебный прототип).
По видео определяет людей и проверяет, есть ли на каждом **каска** и **сигнальный жилет**. Нарушение фиксируется,
если СИЗ отсутствует непрерывно несколько секунд. Записи попадают в журнал (смены, календарь), по ним формируется акт в Word.

## Как это работает

```
видео → YOLO (человек, каска, жилет) → трекинг людей (#ID) → привязка СИЗ к человеку
      → зона (А) → правила зоны → нарушение держится ≥ N секунд → запись в SQLite + фото → окно, журнал, акт .docx
```

- **Привязка СИЗ к человеку** (`svision/rules.py`): каска должна быть в области головы человека, жилет на торсе. Каска, лежащая на земле, не засчитывается.
- **Подтверждение по времени**: нейросеть иногда «не видит» каску даже на добросовестном работнике (recall каски ~0.75), поэтому решает не один кадр, а **окно** `confirm_seconds` (3 с): нарушение фиксируется, если СИЗ отсутствовало как минимум в `violation_ratio` (80%) кадров окна. Нарушение считается устранённым, когда в окне `clear_seconds` (2 с) СИЗ есть хотя бы в `resolve_ratio` (50%) кадров.
- **Защита от дублей**: если человек потерял трек и получил новый номер, то нарушение на том же месте не записывается второй раз.
- **Люди без идентификации**: система называет их «#3» (номер на видео), а нарушителя по фото и времени определяет ответственный человек.

## Структура

| Путь | Назначение |
|---|---|
| `main.py` | запуск программы |
| `config/default.json` | зоны, обязательные СИЗ, пороги, смены, пути, классы модели |
| `svision/rules.py` | правила и подтверждение нарушений (ядро) |
| `svision/tracking.py`, `detector.py`, `pipeline.py` | трекер, обёртка над YOLO, конвейер кадра |
| `svision/storage.py`, `shifts.py`, `report.py` | журнал SQLite, смены, акт Word |
| `svision/ui/` | окно: вкладки «Мониторинг» и «Журнал нарушений» |
| `training/train_ppe_colab.ipynb` | обучение модели в Google Colab |
| `tools/` | тестовые данные, замер скорости, экспорт в OpenVINO |
| `tests/` | автотесты (`pytest`) |

## Установка (PyCharm 2021.2.2, Python 3.10, Windows)

1. Положите проект в папку **без кириллицы в пути**, например `C:\security_vision` (OpenCV на Windows плохо открывает файлы по русским путям).
2. PyCharm → *File → Open* → папка проекта. *File → Settings → Project → Python Interpreter → Add → New Virtualenv* (Python 3.10).
3. Внизу вкладка *Terminal*:
   ```
   pip install -r requirements.txt
   ```
4. Для тестов дополнительно: `pip install pytest`.

## Модель СИЗ

Нужны обученные веса. Обучение займёт 30–45 минут в бесплатном Google Colab:

1. Откройте `training/train_ppe_colab.ipynb` в [Colab](https://colab.research.google.com) (*Файл → Загрузить блокнот*), включите *T4 GPU*.
2. Выполните ячейки сверху вниз, подсказки в самом блокноте. Нужен датасет в формате YOLO с классами person, hardhat, safety vest (лучше ещё NO-Hardhat, NO-Safety Vest), например Roboflow *Construction Site Safety*.
3. Скачайте `ppe_result.zip`. `best.pt` положите в `models/ppe.pt`.
4. В архиве также лежат графики и `metrics.json`: это материал для раздела отчёта о качестве.

**Ускорение на Intel (рекомендуется):** процессор Intel быстрее работает с форматом OpenVINO. В моём замере на Intel-процессоре в 2.9 раза быстрее, чем PyTorch (на вашем ноутбуке цифры будут ниже, замерьте).
```
python tools/export_openvino.py
python tools/benchmark.py models/ppe.pt models/ppe_openvino_model
```
Затем в `config/default.json` поставьте `"path": "models/ppe_openvino_model"`.

## Запуск

1. Положите видео в `data/videos/site.mp4` (или выберите файл кнопкой «Открыть видео…»).
   Лучше всего подходит неподвижная камера на высоте 4–6 м, 5–15 м до людей, 1080p, голова человека в кадре не мельче ~40 пикселей.
2. `python main.py`, затем кнопка **«Старт»**.
   Источник можно задать и в командной строке: `python main.py --source data/videos/other.mp4`, номер веб-камеры `--source 0` или `rtsp://...`.

Вкладка **«Мониторинг»**: видео с разметкой (зелёная рамка — всё в норме, жёлтая — идёт проверка, красная — нарушение), таблица текущих нарушений, текущая смена, кнопка выгрузки акта.
Вкладка **«Журнал нарушений»**: календарь (даты с нарушениями красные) → три смены (красная — были нарушения) → таблица и фото → *«Выгрузить акт нарушений…»*.

## Тестовые данные для календаря

Реальных наблюдений за месяц у прототипа нет. Чтобы показать календарь и акты, создайте **тестовые записи**:

```
python tools/seed_demo_data.py --clear
```

Такие записи помечены в таблицах «тестовая запись», а в акте стоит предупреждение. В отчёте нужно прямо указать, что исторические записи тестовые. Записи из реальной обработки видео создаются автоматически и помечены как обычные.

## Настройка (`config/default.json`)

- `zones`: зоны контроля. `polygon` в долях кадра (0–1), `required`: `["helmet", "vest"]`. По умолчанию одна зона А на весь кадр.
- `rules`: `confirm_seconds`, `clear_seconds`, `violation_ratio`, `resolve_ratio`, `min_person_height_frac` (мелких людей вдали не оцениваем). Если на добросовестных работниках появляются ложные нарушения, увеличьте `violation_ratio` (до 0.9) или `model.conf`, если нарушения пропускаются, уменьшите.
- `shifts`: смены (по умолчанию три по 8 часов).
- `model.class_map`: какие названия классов модели считать «каской», «жилетом» и т.д.
- `report.legal_basis`: нормативная база в шапке акта. **Номера и редакции документов проверьте по актуальным версиям перед сдачей.**

## Ограничения (стоит написать в отчёте)

- Система видит, что на человеке есть объект, похожий на каску или жилет. Она не проверяет исправность, сертификацию, застёгнутый ремешок.
- Точность зависит от датасета и ракурса: далёкие и частично закрытые люди распознаются хуже.
- Трекер простой (по пересечению рамок): после долгого перекрытия человек может получить новый номер.
- Нарушителя не идентифицирует (вариант «А»): личность устанавливает ответственный по фото.
- Система вспомогательная: решение о взыскании принимает человек (ответственный за охрану труда).
